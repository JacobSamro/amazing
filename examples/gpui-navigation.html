FILE RESPONSE · AMAZING-NET

A fetched document is in the viewport.

The address bar initiated a file response, then Amazing parsed this HTML, collected its style element, ran layout, and painted the resulting page.

NETWORK RESPONSE → DOM → CSS → LAYOUT → RGBA8 → GPUI

This fixture is intentionally local and deterministic. The same adapter accepts plain HTTP responses; HTTPS remains explicit until the vetted TLS exception lands.

Document height is content-driven.

Amazing paints beyond the first screen instead of flattening every page into a fixed viewport.

Wheel scrolling stays in GPUI.

The native shell clips and scrolls one engine-owned pixel surface while the browser chrome remains fixed.

One boundary, two responsibilities.

The engine owns web semantics and pixels. GPUI owns windowing, input routing, composition, and presentation.
