# LAYOUT-39: layout containment boundaries

Fixed base `c5a837a9323a7206a28fb156dbfd67494b0d2778` already includes LAYOUT-38 and unchanged CSS31/32/33 dependencies. Implements the layout-owned boundary effects of applicable containment: independent float/margin formatting contexts, absolute and fixed padding-box containing blocks, and external baseline suppression. Fixed containing blocks are inherited separately from relative/absolute positioned blocks; nested containment replaces both. Static contained grid boxes generate their grid-area containing blocks.

Rules follow [CSS Containment 2 layout containment](https://www.w3.org/TR/css-contain-2/#containment-layout) and [paint containment](https://www.w3.org/TR/css-contain-2/#containment-paint). Principal boxes excluding non-atomic inline, internal ruby and internal table boxes other than cells are eligible; absent principal boxes are excluded. Tables, wrappers, cells and captions remain eligible. `content`/`strict` and `content-visibility:auto/hidden` activate layout effects. Paint alone supplies formatting/positioning boundaries but retains descendant baselines. Five grouped regressions cover applicability, float/margin isolation, baseline distinction, nested absolute/fixed percentage offsets and visibility with a relative intermediary. No upstream implementation was copied.

Paint clipping and stacking context creation were routed to parent for another owning lane. Consumers can use ComputedStyle with the same applicability predicate; an exported shared helper can be supplied if requested. Layout overflow/ink policy, forced-break propagation and fragmentation trapping remain separate follow-ups. This is measured progress rather than complete containment conformance.
