# Completed-job compact fetching

Post-job compact transfer previously queried Boat metadata again. A provider-info failure could therefore prevent fetching results from a successfully completed job.

`linux-run.sh --endpoint-receipt PATH --compact-root REMOTE_ROOT --ref SHA` captures the actual endpoint, lane, full source, box, command hash and a random job identity. The same remote execution publishes a completed marker with its boot identity and exact compact file catalog. The output root must be fresh. `lane-fetch.sh LANE DEST --endpoint-receipt PATH --source SHA FILE...` uses the captured endpoint and verifies the completed marker, boot, identities, paths, byte bounds and hashes. It does not query provider metadata. Missing markers after resume, mismatched identities and altered files fail closed. There is no retry or raw-artifact fallback. `linux-render-wpt.sh` automatically uses this path for each exact-source side. Legacy manual fetch remains available.
