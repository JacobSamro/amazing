# Font-display loading periods

Recorded base: 5efe03ecd6ebf0cbeacca0a4dc24aa55a06f8f58 (origin/dev).
Scope: amazing-text and amazing-text-provider only. Original implementation from CSS Fonts 4 §3.2, https://www.w3.org/TR/css-fonts-4/#font-display-timeline; no copied upstream algorithm or new dependency.

The native timeline belongs to an exact immutable FontFaceDescriptor and survives provider rebuilds through a cloneable native handle. It starts at the first actual face matching use, not the network request. Synchronous loaders and existing register_font_face callers retain their behavior. The asynchronous source interface distinguishes Pending, Failed and actual Ready bytes, preserves src order, and never skips an unresolved earlier source to choose a later one.

UA timing choices are explicit: auto/block use 3000 ms block and unlimited swap; swap uses zero block and unlimited swap; fallback uses 100 ms block plus 3000 ms swap; optional uses 100 ms block and no swap. Load failure becomes visible immediately. Loaded-before-use and loaded-within-period fonts are selected; completion at or after the finite failure deadline stays on fallback permanently. Actual decoding completion, not response arrival, controls the acceptance timestamp through register_font_face_with_clock.

During block, shaping retains the real fallback glyph IDs, advances, metrics, cluster mappings and hit geometry. The provider mints an invisible rendering-font variant through its own FontKey allocator; existing rasterize/rasterize_at_scale then returns no glyph coverage. Visible and invisible variants cannot share raster entries. Display transitions advance provider generation and invalidate old variants/cache entries. Timed provider revisions use store-minted process-unique generations so rebuilding a provider cannot accidentally accept an old invisible glyph key whose local font slot was reused. No Layout/paint boolean, authored script replay, or claimed-but-painted invisible text is introduced.

Typed FontDisplaySnapshot and FontDisplayFaceState expose phase, visibility, metrics source and absolute next deadline. The shell owns its original monotonic page clock, per-document/stylesheet/source timeline custody, actual pending/ready/failure loader results, and same-runtime reflow. Provider timelines must not be reset by resize or DPR change. Registration callbacks release native timeline locks before loader/clock calls. Ordinary synchronous rendering remains unchanged; shell adoption and real window timing are separate consumer qualification.

Ten grouped native controls cover every mode/boundary, first use, real suppressed raster with unchanged fallback metrics, early failure, real font decoding, permanent late failure, rebuild custody, Unicode/source selection, declaration precedence despite completion order, completion after decode, and retained-provider generation separation. Original shell eight-second controls are unchanged.
