# JS36: Empty statement completions and protected finalizers

Statement completion is represented internally as `Option<JsValue>`: `None` is Empty, while `Some(Undefined)` is an actual undefined value. Public values and execution APIs retain their existing schema. Interpreter, resumable generator completion and coroutine segment state preserve the distinction; a TryHandler has `Option<Option<JsValue>>` to distinguish an unsaved completion from a saved Empty completion.

AST StatementList starts Empty and applies UpdateEmpty with its preceding value after every statement, including break/continue propagation. Blocks and labels preserve Empty. If, With, Try and iteration statements apply the undefined fill required by their algorithms. Loops retain the last nonempty body value independently of the next body; switch clauses share the CaseBlock value across fallthrough. Catch starts a fresh StatementList. Normal finally restores the protected try/catch value; abrupt finally replaces it. Disposal saves/restores its protected completion while preserving existing Throw/SuppressedError precedence and active-coroutine await behavior.

The VM adds four operations: `SaveCompletion(value, present)`, `CompleteEmpty`, `UpdateEmptyCompletion(value, present)` and `EnsureCompletionValue`. Each StatementList allocates one reusable saved pair rather than a pair per statement. Loop body and switch list boundaries use the same helper. Compiler completion boundaries unwind inner to outer before an ExitTo using the target's completion depth, so nested List/If/Try/With and labeled break/continue retain the correct UpdateEmpty ordering. Registers already strongly retain their values across suspension. No VmFrame field or Program declaration metadata changes are required. A separate compiler_completions.rs keeps the compiler below the file-size cap.

Existing call dispatch already snapshots/restores completion, and constructors route through that dispatch; these boundaries are preserved. A class element execution scope bypasses ordinary dispatch, so its exact helper now saves/takes completion before its body and restores it on success/error before popping its existing frame. Coroutine segments similarly keep their own completion and restore the driver's completion on leave, without changing invocation identity, home, source context, strictness or scheduling.

The coroutine expression unwinder temporarily represents injected generator Return as an Err sentinel plus a pending-return marker. StatementList and loop-body result boundaries now consume that marker into an explicit Flow::Return, after expression unwind but before disposal, finally or IteratorClose. A for-head disposal boundary applies the same conversion if it is reached first. Real finalizer/disposer/close throws can therefore override Return without being suppressed with the sentinel or mistaken for Return at the outer coroutine driver. The marker remains private and short-lived during expression unwind; Suspend and public schemas are unchanged.
