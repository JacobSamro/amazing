# External XML source contracts

Native parser input must be explicit: a caller-issued document source/base, a resolver callback receiving declaration-base/system/public IDs and entity kind, and successful immutable accepted bytes with an actual resource identity/base and optional real transport charset. The parser must not open a SYSTEM path or manufacture a browser ClientContext. The corpus adapter can provide actual pinned-archive filesystem reads within its declared resource root; installed browser loading requires the real receiving Document/native Fetch policy seam.

The default no-resolver parser remains nonvalidating and does not claim it read external resources. Validity constraints (content-model validity, proper declaration/PE nesting and proper conditional-section/PE nesting) must remain distinct from well-formedness constraints. Original corpus eligibility and expectations remain unchanged; any genuine normative/oracle conflict is recorded, not reclassified.

The completed document-entity encoding ticket `607a60e8` is a separate real prerequisite published as `e94856c5`. The new external-entity text declaration has different grammar and cannot be replaced by a document declaration or MIME fixture wrapper. No allocation is authorized until the whole external-resource source/control/corpus plan is frozen and reviewed.

Runtime Reporting creation prerequisite on the fixed published tree: native Net `ReceivingDocumentClient` is available, but HTML has no immutable receiving-environment/creation-URL factory. Required adapter must capture the actual Window/Document/generation/Realm and native origin/security/ancestor/cookie/partition facts at real creation/admission, preserve distinct creation/current/base URLs, then register a genuine Net ReportingDocument from an authentic accepted head or explicit fresh-initial source. Status/referrer/headers cannot be synthesized from the current URL. Original-scope reservations capture this registered capability before SPVE and never relookup after listener retirement. Runtime owns completion/pump consumption; this XML parser does not provide a substitute factory.

## Concrete receiving-client creation interface for Runtime

The actual driver producer must own a private `HtmlReceivingCreation` record, created only at native Window/Document association commit. Its identity is `{ realm: RealmHandle, window: u64, document: NodeIdx, generation: u64 }`; native zero node/window keys remain valid. The record retains immutable creation URL, native committed origin (including the actual opaque identity), original policy-container CSP self-origin/full enforced/report-only COEP, real security/cookie/partition/ancestor/context facts, and original admission kind. Current Document URL/base/referrer policy can update through their actual native algorithms without rewriting creation origin/URL.

Proposed consumer contract: `receiving_document_client(identity) -> Result<ReceivingDocumentClient<ReceivingDocumentIdentity>, DomError>` validates the real native association/retained creation record and supplies the existing required Net factory fields. `receiving_document_report_context(identity) -> Result<ReceivedReportContext, DomError>` returns the original admitted response status/referrer and explicit received-versus-initial classification. No current caller/global/proxy or final-URL reconstruction is permitted. A received admission takes the actual sealed accepted head/full ordered headers from the loader; a fresh initial admission takes the actual native creation receipt. Initial-literal/file cases never fall back from a failed HTTP response.

A separate actual service registration checkpoint consumes that capture and genuine response headers or fresh-initial classification, returns a service-bound `ReportingDocument`, and binds it to the same immutable identity before author code. Runtime's original-scope capture/reservation then consumes this registered handle before SPVE, binds only actual returned ReportIds afterwards, and retains that original pair through retirement. Factory capture is not registration, admission is not terminal delivery, and retargeting/recreating a Window cannot replace old authority. Existing `WindowContext.fetch_origin` is the origin input; mutable `document_url` alone cannot supply creation custody. The current same-global origin reset in `html_set_document_origin` must be corrected by the producer, not hidden by its getter.
