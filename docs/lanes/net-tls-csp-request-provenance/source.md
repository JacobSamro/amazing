# Native external CSP request provenance

Unbuilt/unqualified distinct successor to qualified Reporting9de. All original policy enforcement checks remain; native receipts now retain the policy-qualified report authority instead of only legacy diagnostic fields.

[CSP 2.4.2 and Fetch integration](https://w3c.github.io/webappsec-csp/#create-violation-for-request) create request violations against the exact checked policy and effective directive. Each native CspViolation retains private policy index/snapshot, effective/source directive, CspRequestPhase (PreRequest/PostRequest/WebSocketPreRequest), real Request URL chain/origin/self-origin and original resource URL. Legacy public directive/disposition/blocked_url remain diagnostics; editing them cannot replace saved report authority. Non-HTTP websocket resource provenance remains its actual original scheme.

CspViolation::enrich_request_report(&ReceivingDocumentClient, &saved Request, &CspRequestReportContext) -> Result<CspReportViolation,CspRequestEnrichmentError> validates matching native request/receiving/policy custody. Service completions after real redirects can use enrich_saved_request_report(&ReceivingDocumentClient,&source), which consumes the immutable native check receipt, without reconstructing an internal Request URL chain in HTML. Neither method infers a receiving global from finalURL. Native driver still validates original Window/Doc/generation. Source metadata includes actual element/referrer/status/sourceFile/line/column. Original policy UTF16 units and exact report-to/report-uri routes come from the retained checked policy, including multiple policies using the same fallback. Request resource uses original Request URL per CSP, avoiding substituted final-target disclosure. Samples remain empty for external request reports.

CspReportViolation names the shared genuine CSP dictionary; CspInlineViolation is a compatibility alias for the existing inline producer. No inline blockedURI or fake inline source is created for external requests.

CspRequestElement takes internal exact UTF16 nonce, present flag, native attributes/duplicates and parser-inserted provenance. Request::apply_csp_request_element uses the same native nonceability helper as inline behavior. ApiRequest::apply_csp_request_element(CspExternalElementKind::Script/Style,&receipt) supplies an ordinary browser-only preparation seam; private validated nonce/parser metadata survives genuine Request constructors/clones and reaches real PendingFetchApi/NetworkService policy checks. ApiRequest::apply_receiving_csp_client(&actual client) validates native origin and preserves protected CSP self-origin separately, including sandbox-opaque receiving origin. JS Request has no setter for these trusted native fields.

Meaningful native controls cover independent enforce/report-only/Meta policies, exact invalid UTF16 original-policy custody, fallback/effective directives, diagnostic mutations, pre/post/WebSocket receipts, original-resource privacy, stale request/policy/origin rejection, valid/absent/duplicate/dangling-markup/invalid nonce units, real API constructor/clone + actual successful GET peer versus pre-admission blocked request, and opaque native receiving origin with distinct protected CSP self-origin. These controls do not prove installed classic/module loading or event/observer/native report delivery; HTML owns authentic source-element custody and its event-before-report consumer checkpoints. Existing report/transport controls remain intact.

Full before/after gate includes workspace nextest/doctests, browser build, original eleven-directory CSP WPT and complete TLS/net/fetch test-support suites. Whole source/commands freeze precedes any dedicated compute allocation; compact identity/loss evidence only, raw output remains remote.
