# JS35: Synchronous delegated-yield IteratorRecord protocol

Synchronous `yield*` now uses one shared strong iterator record in the VM and coroutine adapter. Actual GetIterator applies to arrays and primitive strings, including overridden iterator methods and live native Array iterator length. The record captures `next` once without premature callable validation. `throw` and `return` are looked up per resumption with semantic GetMethod: null/undefined are absent; other noncallable values throw. Missing throw performs normal IteratorClose before the protocol TypeError, preserving close errors; absent return returns the resumption value.

A live inner iterator result is forwarded as the original object without reading `value`. `done` is read once by delegation; `value` is read only for a done result. New `FrameOutcome::YieldedIteratorResult` and coroutine `Suspend::YieldIteratorResult` carry that object to the synchronous driver, preserving getters, descriptor shape, proxy identity and result identity. VM record state is cleared on completion and every step error; coroutine stack ownership releases the record on unwind. No iterator/object RefCell borrow remains across JavaScript calls.

The algorithm adapts `lucid-softworks/lumen`, `crates/lumen/src/eval.rs`, `yield_delegate` and GetIterator at `f6c9860d44fa52249cfd647122edea184d32c863`, MIT, Copyright (c) 2026 Lucid Softworks limited. File headers and the appended notice row identify the new helper and raw-result adapters. Only std and Amazing's existing value types are used.

Parent and VM owner granted the shared record/helper, sync YieldDelegate consumer and raw-result variants/consumers. Call context, invocation token, source-context environment, VM declaration instantiation, async_delegate and job scheduling are unchanged. Strong JsValue/Rc ownership retains iterator, next and result across suspension; no collector/tracing or serialized state schema exists here. The coroutine handoff retains its existing exclusive ping-pong contract.

The AST async-generator fallback retains its existing synchronous wrapping/value-extraction policy, identified from its already captured own-function is_async metadata. This change makes no async scheduling conformance claim. Its whole corpora guard regressions, while faithful VM asynchronous delegation continues through the existing separate state machine.
