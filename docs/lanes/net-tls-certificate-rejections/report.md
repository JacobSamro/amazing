# TLS certificate rejection boundary

Base: ccbe84327b1e177cdf05bc4d9b6ce27b433e4b5f (`origin/dev` when isolated).

Pinned rustls 0.23.43 already performs real chain, signature, server-auth EKU,
validity and SAN identity validation using Mozilla trust roots. The adapter
previously flattened every failure to text and retained the rejected handshake.
This ticket exposes stable provider-neutral certificate reasons and ALPN failure,
and drops a fatal handshake's socket before returning its error. A later step
cannot publish a stream from the rejected connection. Existing callers continue
to receive errors; no trust override or custom verifier is introduced.

The opt-in real loopback TLS corpus covers DNS case/trailing-dot matches, IPv4
and IPv6 SANs, wrong identities, one-label wildcards, rejection of CN-only and
DNS-encoded IP identities, expired/future certificates, client-only EKU,
unhandled critical extensions, corrupted signatures, complete/missing
intermediate chains and ALPN mismatch. All original fixture bytes are preserved.
New certificates use an independent public test CA/key generated by the pinned
fixture script. Cryptographic validation remains entirely inside the vetted
provider; there is no algorithm port or new dependency.

Provider API: https://docs.rs/rustls/0.23.43/rustls/enum.CertificateError.html
Service identity: https://www.rfc-editor.org/rfc/rfc9525.html
